# RescueFlow AI · AdaHack 2026

[Play the product film](out/RescueFlow-AdaHack.mp4). The master runs 100 seconds at 1920 × 1080, 30 fps. It has an original stereo score and can be watched muted.

## Render or edit

From the repository root, run the following with Node.js and npm installed.

```sh
cd video
npm ci
npm run render
```

The first render downloads Remotion's pinned headless browser if it is missing. After setup, rendering uses local files. It does not start the app, call an AI provider, fetch map tiles, or require SUMO. The render writes `out/RescueFlow-AdaHack.mp4`. Run `npm run studio` for the editable timeline, or `npm run typecheck` to check TypeScript. Production used Node 26.5.0, Remotion 4.0.545 and Windows fonts. Font substitutions can change line widths on other operating systems.

## Evidence and reconstructions

- **City and decision shots.** The Ljubljana desk shows a captured state from the current branch. The separate, labeled training-grid example uses the published first-generation option set. Its three alternatives, assignments, route edge lists and pickup estimates come from the planners at simulation second 86. The archived OpenAI response ranked B, C, A. The newer desk also supports a waiting-queue strategy.
- **Approval.** The frontend plates are the actual dashboard rendered against snapshots. Option selection and the approval gesture are staged to demonstrate the operator workflow. The following positions are a 22× replay of the benchmark executing the same plan under its automatic approval protocol. They are sampled each simulation second and interpolated per vehicle. The preference percentages are the stored model's preferences over feasible choices.
- **Signals and practitioner input.** The illustrated junction shows an eligible urgent approach as a separate example. The controller may shorten the remaining conflicting green to six seconds and preserves programmed clearance phases. The field workflow is informed by the reported conversation with an ambulance driver who previously worked in dispatch. The crew-navigation handoff is illustrative.
- **Simulation wall.** Six verified recordings repeat at different time offsets as the camera pulls back. The final register encodes all 5,000 attempts from the published summary, ordered by policy and seed. Cell brightness encodes capped response, and red marks the five invalid runs. Confirmed reproductions cover seeds 0/A1, 1/B1, 2/R1, 3/B0, 4/A2 and 5/B1. Each replay reproduced the corresponding archived call-by-call responses.
- **Results.** Positive seconds saved means the candidate's response was faster than the reference. Differences average matched scenario means, with a 900 s cap and missed-call score. Intervals come from the published paired bootstrap. The original 1,000-scenario study supports the numbers shown. The checkout includes a queue-aware successor and fresh-seed launch instructions, but no completed fresh-seed result bundle. See the [published summary](../experiments/published/montecarlo-2026-11-22/summary.json) and [methods](../docs/EXPERIMENTS.md).

## Optional recapture

The plates and small trajectory extracts are included. To rebuild them, use Python 3.11+, the project core dependencies, SUMO 1.28.0 with TraCI/sumolib, and pyproj. Set `SUMO_HOME` to the installation with its `bin` and `tools` directories. From the repository root run `python video/scripts/capture.py`, then from `video/` run `node scripts/plates.cjs`. The capture script only reads archived model responses, verifies each replay, and keeps scratch files in `.capture/`. Render assets and the score are regenerated by `npm run prepare-assets`.
