## Objective

Turn stage 1's validated schedule, candidate plans and SUMO smoke into a **single coherent event-driven transport simulation**. When a dispatcher-approved plan changes, vehicles must physically change routes in SUMO; simulated pickup/delivery, equipment custody, hospital handovers and green-wave requests must update the authoritative world. The crew's existing Google Maps navigation remains outside this simulator. Assignment messages are mocked only.

## Required implementation

1. **Single-owner simulator.** Create/complete a `SimulationController` process/class that exclusively owns a TraCI connection. API/UI/LLM callers enqueue commands; only the controller steps SUMO, mutates its vehicle states and observes positions. Separate `sim_time_s` from wall-clock; support fixed-step headless run, pause/resume/reset, configurable faster playback and deterministic seed; publish serializable snapshots. Make it work headlessly first. Handle launch/termination/connection errors honestly; no silent fallback to fake vehicle motion. Track SUMO version, network version, scenario IDs and command acknowledgements.
2. **Physical service execution.** Spawn/move five fictitious ambulances on valid SUMO edges. For each planned stop, confirm arrival, apply actual simulated dwell/load/unload/handover time, update pickup/delivery task status, next route, vehicle availability and patient/equipment custody **only on completed service**. Keep the fixed prefix for completed/in-progress tasks when replanning. Broken R2 stops and is never sent onward. Another vehicle approaches R2's physically reachable stop, waits transfer duration, collects K1 and later delivers it; K1 must not teleport or duplicate. If SUMO vehicle stops are hard, implement deterministic controller-level service-state dwell that still respects physically observed arrival.
3. **Road disruptions.** Implement a planned closure of an actual road edge, recognized identically by B0/A1 and applied in SUMO as well as in planning ETA queries. Recompute valid detours; block routes that include a closed edge. Use a supported SUMO rerouter or equivalent actual lane/edge restriction; if you must restrict the closure to roads *ahead of* vehicles, document that assumption. Do not teleport the broken vehicle or move other vehicles instantly. Both policies continue to respond to events.
4. **Resource and constraint events.** Implement events for `vehicle_delay`, `priority_changed`, `hospital_capacity_changed`, and `helicopter_grounded` on top of the existing validated state. Fog grounds HELI_1 for 3600 simulated seconds. Helicopter flight ETA is an **analytical** 200 km/h abstraction plus documented handling overhead; don't inject helicopter into SUMO. Hospital receiving capacity must gate completion/feasibility. Maintain an explicit infeasibility report instead of forcing unsafe reassignment.
5. **Optimization and alternatives.** Complete/improve A1 plan insertion/local search with a hard wall-clock solve budget and at least two meaningful strategies. OR-Tools is optional, not a requirement if a tested deterministic algorithm already handles the small dataset. Log solver objective, selected actions, rejected infeasible candidates and ETA assumptions. Keep B0 a credible nearest-eligible + local repair policy with matching information, rules and dispatch handoff. Alternative planning never writes into committed state.
6. **Intelligent green wave (simulation-only).** For *authorized simulated urgent legs only*, identify upcoming signalized junctions via TraCI (`getNextTLS`) and their controlled link/phase logic. Stage a priority request ~10–25 simulated seconds before arrival, ideally queue-aware; use **compatible phase transitions with minimum green, yellow and any necessary all-red clearance**, not arbitrary traffic-light color strings and not an LLM command. Limit to 1 junction first, then 3 on the ambulance's route; timeout and restore normal phase program after passage, reroute or failure. Conflicting emergency requests must be resolved deterministically. Log signal requests, phase changes, restoration and civilian delay. Do NOT connect to real traffic controllers.
7. **Emergency-driving fairness.** SUMO has blue-light emergency behavior, including passing red lights and potentially rescue-lane responses. B0 and all enhanced policies must use the same appropriate emergency vehicle flags, speed parameters and civilian demand. Routine patient/equipment transports must not obtain unjustified siren privileges. If green-wave gains are small with the built-in blue-light device, **do not falsify gains by disabling it only in B0**. Document the chosen model and the limitations.
8. **Dispatch adapter behavior.** On a successful approved new assignment or revised assignment, record a simulated outbound unit notification and optional simulated receipt. No real phone number, radio, Google Maps key, external traffic provider or patient data. Preserve the actual operator gate and idempotent commit semantics.
9. **Optional repositioning** only **after** the above genuinely works: move an idle, eligible unit toward preselected staging zones according to fixed prior synthetic demand weights, no future call peeking. Record moves as planned tasks; otherwise leave this documented stretch feature disabled rather than half-implementing it.
